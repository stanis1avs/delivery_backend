# Delivery

[frontend](https://github.com/stanis1avs/delivery_frontend)

Проект сервиса доставки — приложение для курьеров. За основу взят [макет Figma](https://www.figma.com/design/cZ3pCVoUAQUSqmNyXH1PtN/Delivery-Service-Dashboard---Admin-Panel--Community-?node-id=0-1&p=f&t=3kIzuy2rIRglQLOK-0).

[Функционал приложения](https://github.com/stanis1avs/delivery_frontend/blob/master/FUNCTIONAL.md)


### Основная функциональность:
- Авторизация через Telegram Login Widget
- Real-time трекинг геопозиции курьеров (Geolocation API → PostGIS)
- Назначение заказов ближайшему свободному курьеру (ST_DWithin + рейтинг)
- Расчёт маршрута и времени доставки через OSRM
- Интерактивная карта с маршрутом и маркерами курьеров (Leaflet)
- Уведомления курьеру через Telegram Bot с подтверждением заказа
- Real-time обновления заказов и позиций на карте (WebSocket / Socket.IO)
- Система надёжности курьера: рейтинг, выполненные заказы, среднее время принятия

## Запуск

```bash
docker compose up -d postgres redis osrm
npm install
npm run migrate     # применить миграции
npm start           # API + WebSocket + Telegram-бот + воркер распределения
```

Одна команда `npm start` поднимает всё: HTTP-API, WebSocket, Telegram-бота и воркер распределения заказов. Отдельно ничего запускать не нужно.

## Воркер распределения заказов

Фоновый цикл, который раздаёт заказы курьерам. Стартует внутри `index.js` вместе с сервером и каждые 5 секунд делает один проход:

1. Возвращает в очередь заказы, приглашение по которым истекло (курьер промолчал).
2. Берёт все заказы в статусе `Pending`.
3. Для каждого вызывает `findBestCourier` — PostGIS ищет свободных курьеров в радиусе 10 км, OSRM считает реальное время в пути, побеждает минимальная оценка `время − рейтинг × 30`.
4. Резервирует выбранного курьера атомарным `SET NX` в Redis, чтобы один курьер не получил два заказа сразу.
5. Отправляет ему уведомление в Telegram с кнопками «Принять» / «Отклонить», заказ переходит в `Waiting`.

Дальше решает курьер: **принял** — заказ становится `Progress`, курьер помечается занятым; **отклонил** — заказ возвращается в `Pending`, а этот курьер исключается из подбора по нему; **промолчал** — через 5 минут приглашение истекает, заказ возвращается в очередь. Любая из трёх реакций пересчитывает рейтинг курьера.

Чтобы вынести воркер в отдельный процесс (например, при масштабировании), поставьте `WORKER_IN_PROCESS=false` и запустите:

```bash
npm run worker
```

## Тесты

88 тестов на `vitest`, шесть уровней — гео-модуль, API и авторизация, воркер, Telegram-колбэки, WebSocket, конкурентные сценарии. Идут против **живых** PostgreSQL и Redis: логика подбора живёт в SQL, и мок этого слоя проверял бы сам мок. Внешние сервисы (OSRM, Telegram Bot API) подменяются локальными HTTP-стабами.

Прогон использует отдельную базу `delivery_test`, которая пересоздаётся с нуля каждый раз — рабочие данные не затрагиваются. План покрытия и разбор подводных камней — в [`TESTING_PLAN.md`](../TESTING_PLAN.md).

E2E-тесты в настоящем браузере лежат во фронтенде: `npm run test:e2e` (Playwright).

## Стенд оценки распределения

Тесты отвечают «назначилось или нет», стенд — «насколько хорошо». Прогоняет синтетический флот и поток заказов через **настоящий** `findBestCourier` и собирает метрики: ETA до забора, время ожидания курьера, доля неназначенных, коэффициент Джини по нагрузке.

```bash
npm run simulate -- --couriers 20 --orders-per-hour 60 --hours 2 --repeat 3
npm run simulate -- --record 1     # + HTML-проигрыватель с картой
npm run simulate:ui                # расставить курьеров и заказы мышью
```

Интерактивный вариант позволяет кликами по карте расставить курьеров (данные подставляются автоматически) и точки заказов, а затем увидеть таблицу **всех** кандидатов с их ETA, рейтингом и оценкой — то есть почему алгоритм выбрал именно этого. Подробности в [`simulator/README.md`](simulator/README.md).

## CI

[`.github/workflows/tests.yml`](.github/workflows/tests.yml) — на каждый push в `main` и каждый pull request GitHub поднимает контейнеры PostGIS и Redis, ставит зависимости, прогоняет тесты и отдельно проверяет, что миграции откатываются и накатываются заново.

## Переменные окружения

Полный список с комментариями — в [`.env.example`](.env.example). Ключевые:

| Переменная | Смысл |
|---|---|
| `DB_*`, `REDIS_*` | Подключения к базе и Redis |
| `COOKIE_SECRET` | Секрет сессий и HMAC-токенов курьеров |
| `TELEGRAM_BOT_TOKEN` | Токен бота |
| `OSRM_URL`, `OSRM_DATASET` | Маршрутизатор и набор дорожных данных |
| `WORKER_IN_PROCESS` | `false` — воркер отдельным процессом |
| `TELEGRAM_ENABLED` | `false` — не поднимать бота (для E2E) |
| `COURIER_ONLINE_WINDOW_SECONDS` | Окно, после которого курьер считается оффлайн |
| `RATING_BONUS_SECONDS` | Вес рейтинга в формуле подбора |
